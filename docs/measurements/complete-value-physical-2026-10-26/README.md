# Physical complete-value input boundary check, 2026-10-26

An isolated private character Runner completes two **public stdio MCP
`phone_type` (`clear:false`)** requests on the authorized iPhone 17 Pro Max,
iOS 27.2, through the candidate daemon and an owned UIKit fixture. The App's
independent receipts, not only MCP success, confirm both complete values:

| Seed | App result | Whole public request |
| --- | --- | --- |
| `old` | Exact `old` + 501 characters | 9.56 s |
| 6015 characters | Exact 6516 characters | 21.47 s |

[Sanitized results](summary.json) retain field lengths/hashes and the independent
expected-hash audit. Other fixture fields are unchanged and Return/submit events
remain zero. Native chunk budgets and public request deadlines were unchanged.
The candidate uses the complete-value boundary implementation from the preceding
[Simulator experiment](../complete-value-boundaries-2026-10-26/README.md).

The initial locked preflight stopped before installation or input. Testing
continued only after the operator confirmed unlocking. Only owned fixture/test
Runner apps were installed. Independent cleanup confirms both absent, all 21
preexisting apps preserved, relay/daemon ports closed, no pending input and the
default service still offline, unowned and without a private hold or human handoff.
[Build hashes](build-receipt.json) identify the unsigned/signed private Native and
fixture products; no signing material, device identifier or credentials are included.

This verifies two positive append cases. It does not verify the full Simulator
negative cohort on hardware, physical replacement/veto/focus-switch behavior,
older iOS versions, latency superiority, or the installed product default path.
No product Native source or default capability was promoted by this experiment.
